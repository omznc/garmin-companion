# /v2: the paid cloud coach

This is the contract for the app. The base URL is `https://coach.omznc.workers.dev/v2`.
`/v1` is frozen for v0.9.1 users. New apps call only `/v2`.

## Rules

- Free users are anonymous. They use an **install id**. Each install id gets 30 credits a day (UTC day, no rollover).
- Premium users sign in with an email code. They use a **session token**. They get 400 credits a day and 6000 a month. When they pass a limit, they fall back to the free 30 credits.
- Send the token in every call except `install`, `auth/email/*` and `webhooks/polar`:
  `Authorization: Bearer <install id or session token>`.
- An install id is 32 hex characters. A session token is `s_` and 64 hex characters.
- 1 credit is 0.0005 USD of model cost. A typical question costs about 4 to 5 credits.
- Every error has the OpenAI shape. Act on `error.type`, not on the message:
  `{"error": {"message": "...", "code": 402, "type": "out_of_credits", "resets_at": "..."}}`
- The worker never stores or logs message content.

## Routes

### `POST /install`

No auth, no body. Returns `{"id": "<32 hex>"}`. Store it in the keyring.
Limits: 3 ids a day per network (an IPv6 network is a /64), 5000 a day in total. The app calls it only when the first cloud question is sent or when the person opens the coach settings. Errors: `429 rate_limited`, `429 install_limit` (both have `Retry-After`).

### `GET /balance` (also `GET /me`)

Returns:

```json
{
  "plan": "free",
  "premium": false,
  "email": null,
  "source": null,
  "renews_at": null,
  "cancels_at_period_end": false,
  "credits_remaining": 30,
  "daily_grant": 30,
  "resets_at": "2026-10-19T00:00:00.000Z",
  "month_used": 0,
  "month_ceiling": 6000
}
```

- `plan` is `free` or `premium`. `source` is `polar` (later `app_store` or `play`).
- `credits_remaining` is whole credits, rounded down. For premium it is the premium room plus the free room.
- `resets_at` is the next UTC midnight. `month_used` and `month_ceiling` count premium credits only.
- `email` is set for a signed-in user.

### `POST /chat/completions`

OpenAI-compatible. Body limit: **100,000 bytes** (the Haiku profile). A larger body gets `413 context_too_large`. The app caps each tool result at about 25 KB, drops the oldest tool results, and retries once.

Request headers:

- `X-Request-Id`: a new UUID for each HTTP request. 8 to 64 characters of `[A-Za-z0-9_-]`. The worker holds credits under this id. A second request with an id that is in flight or was already charged gets `409 duplicate_request`. A request that failed before any charge may use the id again. If the header is missing, the worker makes one up.

Request body: `messages` (1 to 80), and optionally `stream`, `tools`, `tool_choice`, `response_format`, `max_tokens`, `temperature`, `reasoning`. Other fields are dropped. Only text is accepted: `content` is a string or a list of `text` parts, `tools` hold only `function` tools, `tool_choice` is a string or names a function, and `reasoning` holds only `effort`. Anything else gets `400 bad_request`. The worker sets the model. A `model` field that does not match is rejected with 400. Do not send a model id. `max_tokens` is capped at 4096 for free users and 8192 for premium. The hold uses the capped value, so a smaller value holds fewer credits. The app sends 3000. The worker adds `usage` and `stream_options.include_usage`.

Response: the upstream body, as SSE when `stream` is true, as JSON when it is not. Headers:

- `X-Credits-Remaining`: whole credits left. For a stream, it is the value before this request is charged. For JSON, it is the value after. Call `GET /balance` for the exact figure after a stream.
- `X-Credits-Reset`: the next reset, ISO time.

Charging: the worker holds an estimate first. The prompt counts as 1 token for each 3.5 body bytes, and the answer counts as `max_tokens`. The estimate is not a strict bound: the charge never exceeds the hold, so rare text that costs more is absorbed by the service. The worker then charges the real cost from the token counts. If the client leaves after the usage block was read, the real cost is charged. If the stream ends without a usage block, or the client leaves before it, the hold is charged. A hold that is not settled in 5 minutes is charged in full. If the model call fails before any content, nothing is charged. This includes an `error` chunk that comes inside a 200 stream before any content: the app must treat such a stream as a failed call. A JSON answer with an error gets `502 upstream_error`.

Errors:

| Status | `type` | Meaning and what the app does |
|---|---|---|
| 400 | `bad_request` | Bad JSON, no messages, too many messages, wrong model, a tool, content part or reasoning field that is not allowed. |
| 401 | `missing_token` | No bearer token. |
| 401 | `unknown_install` | The install id was not issued here. Call `POST /install` again and retry once. |
| 401 | `session_expired` | The session is gone or expired. Ask the user to sign in again. |
| 401 | `login_required` | The server needs a sign-in (the `FREE_REQUIRES_LOGIN` switch). Show sign-in before the first question. |
| 402 | `out_of_credits` | No credits. Has `resets_at`. Show the upgrade card. |
| 403 | `blocked` | The id or user is blocked. |
| 409 | `duplicate_request` | The request id was used. Do not retry with the same id. |
| 413 | `context_too_large` | Body over 100,000 bytes. Trim and retry once. |
| 429 | `fair_use_ceiling` | Premium limit reached and the free grant is spent. Has `resets_at`. |
| 429 | `rate_limited` | Over 30 requests a minute. Has `Retry-After`. |
| 503 | `coach_paused` | The spend limit is reached. Free and premium spend have separate limits (`DAILY_BUDGET_V2_USD`, and the optional `DAILY_BUDGET_V2_PREMIUM_USD`). Nothing is charged. Say "The cloud coach is paused. Try again later, or use your own key." |
| 502 | `upstream_error` | The model provider failed. Nothing is charged. |

### `POST /auth/email/send`

No auth. Body: `{"email": "a@b.com"}`. Sends a 6-digit code that works for 10 minutes. Returns `{"ok": true}`.
Errors: `400 bad_email`, `429 rate_limited` (5 codes an hour per email, plus a limit per network address), `503 mail_unavailable` (no mail sender set up yet), `502 mail_failed`.

### `POST /auth/email/verify`

No auth. Body: `{"email": "a@b.com", "code": "123456"}`. Returns `{"token": "s_...", "email": "a@b.com"}`.
Any unexpired, unused code that was sent to the email works, not only the newest. Each code allows 5 tries, and a wrong try counts against every live code. Errors: `400 bad_request`, `401 invalid_code`, `429 rate_limited` (a few tries a minute per network).
A session lasts 90 days and renews on use. An account keeps at most 3 sessions. The oldest is dropped.

### `POST /auth/signout`

Session token required. Returns `{"ok": true}`. The token stops working.

### `POST /billing/checkout`

Session token required. Desktop only (mobile uses store billing). Returns `{"url": "https://..."}`. Open it in the system browser.
After payment, the Polar webhook makes the user premium. Poll `GET /balance` every 3 seconds for 30 seconds, then every 15 seconds, and again when the window gets focus.
Errors: `401 login_required`, `409 already_premium`, `503 billing_unavailable`, `502 billing_failed`.

### `POST /billing/portal`

Session token required. Returns `{"url": "https://..."}`, the Polar customer portal (cancel, card, invoices).
Errors: `401 login_required`, `404 no_customer` (never bought), `503 billing_unavailable`, `502 billing_failed`.

### `GET /checkout/done`

Public. No token. Polar sends the buyer here after payment (`CHECKOUT_RETURN_URL`). It returns a static HTML page, "Payment done". It does not read the wallet or D1.
The app must still poll `GET /balance`, because the page does not show the plan.

### `POST /webhooks/polar`

Called by Polar only. It checks the Standard Webhooks signature on the raw body (5 minute window). The app never calls it.
Answers: `200` (applied, ignored, or a replay), `400 bad_signature`, `503 webhook_not_configured`, `500 apply_failed` (Polar retries).

## Premium rule

A user is premium when one entitlement row is:

- `active` or `trialing`;
- `past_due` and the first failure was less than 7 days ago.

A cancel at the period end keeps the row `active` (`cancels_at_period_end` is true on `/balance`) until Polar sends the revoke. `canceled`, `revoked`, a full refund, `unpaid` and `incomplete` end premium at once.

## Not built yet

- `DELETE /me` (account erase).
- Apple and Google purchases. The `entitlement` table already has a `source` column for them.
